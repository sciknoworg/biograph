# experiments/ — benchmarking the extraction pipeline against external datasets

Five benchmarks, none of them designed for this project, scored against the extraction
pipeline exactly as it runs today. Everything here is an adapter around
`scripts/build_site.py`'s existing CLI. Nothing here modifies the extraction core, and
`harness/sandbox.py` proves it rather than asserting it.

## The constraint, and how it is enforced

`schema/*.schema.json` and `build_site.py`'s prompt construction, LLM call and validation
are untouched. That claim is mechanical, not editorial:

- Every run copies `scripts/build_site.py`, `schema/*.schema.json` and `frontend/` into a
  throwaway sandbox, records the SHA-256 of each file and the git commit in
  `manifest.json`, and **re-verifies every hash after the run**. A divergence exits 2.
- The sandbox exists because `build_site.py` derives `ROOT` from its own `__file__`, so
  `subjects/`, `data/` and `dist/` are always siblings of `scripts/`. There is no flag to
  redirect them. Running benchmarks in the repository would write thousands of fake
  people into `subjects/` — the accident `paper_evidence/README.md` already records, when
  170 test entities leaked into the pipeline's name resolution.
- The harness imports nothing from `scripts/`. It only ever shells out.

## Layout

```
experiments/
  harness/
    interface.py   BenchmarkDoc / Extraction / Prediction / ScoreReport + the Protocol
    sandbox.py     hash-verified disposable copy of the extraction core
    runner.py      the only module that knows the build_site.py CLI
    vocab.py       the 22 event and 27 relation types, READ FROM schema/
    coverage.py    the vocabulary coverage matrix, generated
    cli.py         run one benchmark end to end
  benchmarks/
    pmoa_tts/      adapter.py (input + output), score.py (their metric), README.md
    biographical/  adapter.py (all four methods), README.md
    bioevents/     adapter.py (trigger anchoring + SemAF roles), README.md
  docs/
    coverage-matrix.md    generated by `python -m experiments.harness.coverage`
    scope-gate-boundary.md  where the gate's boundary sits, and the --ignore-scope ablation
  tests.py         self-checks; no model, no network
  runs/<run_id>/   report.json per run (extractions and cache are gitignored)
```

## The adapter interface

Each benchmark implements four methods (`harness/interface.py`):

| method | role |
|---|---|
| `load(data_root, limit)` | **input adapter** — native format → text for `--text` |
| `project(doc, extraction)` | **output adapter** — biograph's fixed vocabulary → the benchmark's label space |
| `score(pairs, extractions)` | **scorer** — the benchmark's own published metric |
| `coverage()` | this benchmark's column of the coverage matrix |

Two fields carry the methodological weight:

- **`Prediction.unmapped`** — every extracted item with no expression in the benchmark's
  label space is recorded with a reason. Taxonomy loss is a per-run number, not a
  sentence in a limitations section.
- **`ScoreReport.not_applicable`** — benchmark labels the schema cannot represent
  (Biographical's `occupation`) are named and **excluded from macro-averages**. Scoring
  them 0 would understate the pipeline by averaging in a label it was never asked to
  produce; scoring them at all would claim a capability the data model lacks.

`Prediction.lossy` sits between them: projections that succeeded while losing something
nameable (a three-way collapse onto `family_of`, a year-precision date standing in for an
hour-resolution timestamp).

## How the pipeline is invoked

Fixed in `runner.py`, once, for every benchmark:

```
python <sandbox>/scripts/build_site.py <slug> --text <path> --name <name>
       --domain benchmark_<adapter> --keep-rejected --scope-out <path>
       --model $BIOGRAPH_MODEL --base-url $BIOGRAPH_BASE_URL
```

- **`--keep-rejected` is not optional.** Without it, `extract()` calls
  `os.remove(pdf_path)` on the input whenever the scope gate refuses a document. A
  harness that eats its own corpus on rejection is not a harness.
- **`--strict-scope` is never passed.** Its four extra rules would reject short benchmark
  documents on length alone.
- **`--scope-out` is always passed.** See "Scope-gate attrition" below.
- The API key goes through the environment, never `argv` — it would otherwise land in
  shell history and in every log line echoing the command.

Two CLI behaviours the harness handles explicitly:

1. `main()` runs `build()` after `extract()`, and `build()` exits non-zero when
   validation fails — *after* the JSON is on disk. So a non-zero exit means "the draft
   did not validate", not "no output". The runner reads the document folder either way
   and records `exit_code`; conflating the two would lose a real finding.
2. Extraction samples at `temperature=0.2`. A single run is a draw, not a score. Use
   `--repeats k`; results are cached by `(text, model, core hash, repeat)` so re-scoring
   never re-calls the model.

## Four things found while reading the code that the design has to account for

**1. The scope gate is always on.** `SCOPE_DEFINITION` is in the system prompt on every
call; `--strict-scope` only *adds* four more rules. It asks for "biographical or
historical retrospective essays … intertwined with a specific technology's development".
A `fits: false` verdict writes nothing at all. Three of the five benchmarks are nowhere
near that genre — clinical case reports least of all. So **scope-gate attrition is a
reported column in every results table**, captured via `--scope-out` for every document
including refusals, and adapters that need framing offer it as a disclosed, ablatable
input transformation rather than a quiet workaround.

**2. `note` does carry family subtype.** In 30 of 85 `family_of` relations (35%):
`"Father"`, `"Mother"`, `"Brother"`, `"youngest son"`, `"Jean Brachet was the younger son
of Albert Brachet."` Two shapes — a bare kinship label and a full sentence — and both
give direction. So `ofParent`/`hasChild`/`sibling` can be reported per-subtype **over the
note-bearing subset**, alongside combined family-relation recall over all of it. Which is
a better answer than "not recoverable", and a worse one than "recoverable".

**3. `occupation` is not homeless, but it is not typed either.** `entity.subtype` is free
text and is the literal string `'researcher'` for 1393 of 1975 person entities (71%);
`entity.summary` is populated for all 1975 and usually states a profession in prose.
Neither is a controlled slot. Reported N/A and excluded from the macro-average, with an
optional string-match diagnostic that is labelled as such and never folded into the F1.

**4. Benchmark 2's label space is not a biographical event taxonomy.** It is a subset of
ISO-TimeML — `EVENT`, `STATE`, `ASP-EVENT`, `REP-EVENT` — plus writer-centric SemAF
roles. All 22 biograph event types collapse to one label, so scoring must be
trigger-anchored, not type-matched. And `STATE` is an unreachable recall ceiling by
design: "an event is a dateable occurrence, not a fact or a description"
(`schema/README.md`).

## The date floor

Every event must have a date — "however imprecise … never undated". 66% of the corpus is
year-precision, 14% day. Any scorer comparing a biograph date to a finer-grained gold
must compare an **interval** (`sort_start`/`sort_end`) against a point, which is what
those fields are for. `vocab.contains()` does the hit test and `vocab.resolution_days()`
reports how much the prediction actually committed to, so a containment rate achieved by
predicting "the 1920s" is visibly not the same result as one achieved by predicting a day.

## Licensing — nothing is downloaded or committed by this harness

Every adapter reads a local copy via `--data-root`. Status as found:

| benchmark | licence | status |
|---|---|---|
| 1. Biographical | repo GPL-3.0; **data licence unstated**, distributed via Google Drive, Wikipedia-derived (CC BY-SA upstream) | **unresolved — ask before downloading** |
| 2. BiographicalEvents | repo `marcostranisci/biographicalEvents`, licence not stated in the paper | **unresolved** |
| 3. PMOA-TTS | **CC BY-NC-SA 4.0** — the dataset card's metadata and the repo README agree; the paper's "CC BY 4.0" is the outlier | resolved; downloaded locally, gitignored, **not redistributed**. Derived artifacts published with the paper would inherit NC-SA |
| 4. TLEX | reference implementation **CC BY 4.0**; `pyTLEX` is the Python port | clear for the code; the TimeML corpora it evaluates on have their own terms |
| 5. Grounding | not an external dataset — `--check-grounding` over `subjects/` | no issue |

## Running

```bash
python -m experiments.tests
python -m experiments.harness.coverage --out experiments/docs/coverage-matrix.md
python -m experiments.harness.cli --benchmark pmoa_tts --data-root <dir> --dry-run
```

`--dry-run` loads the corpus, builds the input text and prints what *would* be sent,
without calling a model. It costs nothing, and it is how you check the input adapter and
the slug rules before spending an API budget finding out.

## Built / not yet built

- [x] **3. PMOA-TTS** — built first on purpose: its metric never compares categories, so
      it exercises the whole input/output path with no taxonomy mapping to debug at the
      same time. Two things about the release change the experiment, both documented in
      [its README](benchmarks/pmoa_tts/README.md): it ships **no document text** (rebuilt
      from PMC Open Access, matching the authors' own body boundary) and **no human
      reference timelines** (so the published 0.80/0.95 cannot be reproduced; use
      `--ceiling`, which scores the two released LLM annotators against each other).
- [ ] 5. Grounding — next cheapest; reuses `--check-grounding` over existing `subjects/`.
- [ ] 4. TLEX — needs `pyTLEX` and a TimeML serializer over `events.json`.
- [x] **1. Biographical** — the adapter is built and self-tested; **no data downloaded**,
      because the licence is unresolved. It carries the generalization claim: same
      extractor, different *population* (writers, politicians, athletes) rather than a
      different genre. Three things shape it, all in [its
      README](benchmarks/biographical/README.md): sentences are **grouped by person** into
      one pseudo-document each, so these figures are not comparable to the paper's
      sentence-level numbers and `published_baseline` is deliberately empty; the scope
      gate refuses this population, so it must be run in **both** conditions
      (`--gate-off`); and `occupation` is reported N/A rather than scored 0.
- [x] **2. BiographicalEvents** — adapter built and self-tested; **no data downloaded**,
      licence not stated in the paper or the repository. The most structurally
      mismatched of the five, and the mismatches are the finding: type is not
      measurable in either direction, so scoring is **trigger-anchored** with a
      two-tier anchor (label+quote, then quote alone, counted separately); `STATE` is
      an unreachable ceiling reported as a measured number and excluded from the
      macro; and precision is scoped to annotated sentences, so reading unlabelled
      text is not punished. See [its README](benchmarks/bioevents/README.md).
